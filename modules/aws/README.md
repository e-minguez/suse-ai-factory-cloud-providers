# `modules/aws`

Terraform module for a SUSE AI Factory cluster on AWS: private-subnet
control-plane and GPU nodes behind network load balancers, with the elemental
image built and imported as an AMI. To run it, see
[`examples/aws`](../../examples/aws/README.md); platform behaviour is in
[docs/providers/aws.md](../../docs/providers/aws.md).

> Before the first apply, accept the openSUSE Leap 16 Marketplace listing for
> the account (the jumphost's OS). See [aws.md](../../docs/providers/aws.md#jumphost-ami-marketplace-listing).

## What it builds

- A VPC with one public and one private subnet per zone (`zones`, default the
  first three zones of `region`), one NAT gateway and an S3 gateway endpoint.
- A **jumphost** instance in a public subnet. It builds the image and stays as
  the SSH bastion (output `jumphost`).
- An **internal NLB** with a static private address that is the RKE2 API VIP
  (6443, and 9345 for node joins).
- An **internet-facing NLB** for ingress on 80/443 and `kubectl` on 6443 from
  `api_cidrs`.
- `control_plane_count` (1, or odd and at least 3) control-plane nodes spread across the
  zones, workers from `worker_pools` and GPU workers from `gpu_pools`, all in private subnets.
- IAM roles for the snapshot import and the jumphost, created by the module or
  pre-created with `vmimport_role_name` and `jumphost_instance_profile_name`
  ([aws.md](../../docs/providers/aws.md#pre-created-iam)).
- Everything from one `deploy.sh` run: [one pass](../../docs/providers/aws.md#passes-one).

## Image pipeline

The image is rebuilt only when `build_hash` changes; every build input feeds
it, including `image_rebuild`. `deploy.sh --rebuild` bumps that counter
(`rebuild.auto.tfvars.json`), see [ADR 003](../../docs/decisions/003-rebuild-counter.md).
The AMI name is `<cluster_name>-<build_id>`.

```
jumphost instance (cloud-init writes script + config from user_data)
  -> podman run ... elemental customize --type raw
  -> raw image uploaded to S3 (images/)
  -> aws_ebs_snapshot_import
  -> aws_ami
  -> control-plane and GPU nodes launched from the AMI
  -> RKE2 bootstraps, the charts in release.yaml install
```

`terraform_data.raw_ready` blocks the apply (90 minutes at most) until the raw
image is in S3, using `modules/aws/scripts/wait-for-raw.sh` on the
workstation. Follow the build with `scripts/build-logs.sh` (see
[conventions](../../docs/conventions.md#following-a-build) for remote backends). The snapshot
import and AMI registration show in the `terraform apply` output, not in the
build log.

Details and limits: [aws.md](../../docs/providers/aws.md#image-import),
[ADR 002](../../docs/decisions/002-aws-factory-hooks.md).

## Security

- SSH: only the jumphost has a public IP, with 22/tcp from `admin_cidrs`. Nodes
  accept SSH from the jumphost's security group.
- Ports between nodes and from the NLBs are opened security-group to
  security-group, never by CIDR. The ingress NLB allows 80/443 from
  `ingress_cidrs` and 6443 from `api_cidrs`.
- Nodes have no instance profile and call no AWS API.
- The jumphost role writes `images/*` in the build bucket and has no EC2
  access. The `<cluster_name>-vmimport` role reads `images/*`. With
  pre-created IAM, the roles named by `vmimport_role_name` and
  `jumphost_instance_profile_name` carry the same permissions.
- Node login is `node_username` with `su -`; the image has no sudo.
- `rke2_token` lives in state through `user_data`: treat state as secret.
- The `build_bucket` output is as sensitive as state.

## Cost notes

- One NAT gateway plus per-GB processing; S3 traffic bypasses it.
- Two NLBs, billed hourly plus per-GB and per-connection processing.
- GPU instance types are expensive and need a vCPU quota increase first
  ([aws.md](../../docs/providers/aws.md#gpu-quota-and-drivers)).

## Scripts

- `modules/aws/scripts/wait-for-raw.sh`: blocks the apply until the raw image is in S3
  (see above).
- `modules/aws/scripts/check-and-reserve.sh`: reserves GPU capacity before an apply
  ([aws.md](../../docs/providers/aws.md#gpu-quota-and-drivers)).
- `tools/leftovers/aws.sh <cluster_name> --region <region>`: read-only check after a
  destroy; `deploy.sh --destroy` prints the command
  ([aws.md](../../docs/providers/aws.md#tags-and-leftovers)).
