# Temporary workarounds

Every workaround tied to an upstream defect or an unreleased fix is listed here,
so each can be found and deleted in one go once its removal condition is met.
Code that carries a workaround has a comment pointing to this file.

| Workaround | Where | Upstream issue | Remove when |
|---|---|---|---|
| Terraform 1.16.4 apply crash: `deploy.sh` detects the crash trace, warns that the state may lack created objects, and allows one reconcile and retry. `required_version` stays at `>= 1.16.4` | `scripts/lib/tf.sh` (`tf__version_note`, `tf__crash`), `versions.tf` of every module, example and `tools/multicluster/register` | [hashicorp/terraform#39283](https://github.com/hashicorp/terraform/issues/39283) | Terraform 1.16.5 is released: set `required_version >= 1.16.5` and delete the crash handling |
| evroc crash orphan adoption: after a crash, objects present in the project but missing from state are found through generated `import` blocks, adopted automatically only with `EVROC_ADOPT_ON_CRASH=1` | `tools/orphans/evroc`, `deploy_on_crash` in `examples/evroc/deploy.sh` | [hashicorp/terraform#39283](https://github.com/hashicorp/terraform/issues/39283) | Same as the crash entry; delete `tools/orphans/evroc` with it (`tools/leftovers/evroc.sh` covers the post-destroy check) |
| evroc 409 retry: a failed apply whose log matches `API error (409)` is re-planned and re-applied, up to 3 attempts | `tf_retry_on` in `scripts/lib/tf.sh`, registration in `examples/evroc/deploy.sh` | none filed ([evroc-oss/terraform-provider-evroc](https://github.com/evroc-oss/terraform-provider-evroc)) | the evroc provider retries conflicting load balancer updates itself |
| evroc load balancer defaults pinned in configuration (`ip_protocol_selection`, the health check tuning fields, `http.expected_statuses`): the provider schema has no computed flag on them, so without the pins every plan proposes an update that races the load balancer controller | `modules/evroc/loadbalancer.tf` | none filed (same provider as above) | the provider marks these attributes computed (verify that a second plan is empty before removing the pins) |
| `core_platform_override`, `sysext_image_overrides`: pin a beta OS image and flatten the sysext overrides into the release manifest at plan time | `modules/elemental-config/beta-overrides.tf`, defaults in `modules/common/variables-common.tf` (the `elemental_image` default is also a `beta/uc` image) | none filed (GA `elemental3ctl` 3.0.x ignores `initrdExtensions`; a SUSE beta image is required) | a GA Elemental OS image ships `elemental3ctl` >= 3.1: delete `beta-overrides.tf`, both variables and the `beta/uc` images, and move `elemental_image` to a GA image |
| Precompiled NVIDIA driver override (`gpu_driver_repository`, `gpu_driver_version`, an experimental build) | `modules/elemental-config/templates/elemental/kubernetes/helm/values/gpu-operator.yaml.tftpl`, defaults in `modules/common/variables-common.tf` | none filed (driver packages for SLES 16.1 are not published yet) | precompiled SLES 16.1 NVIDIA driver packages are published under `registry.suse.com/third-party/nvidia` |
| vultr load balancer `ipv4=""` wait and `vultr_snapshot_from_url` completion wait | `modules/vultr/scripts/wait-for-lb-ipv4.sh`, `modules/vultr/scripts/wait-for-snapshot.sh` | none filed ([vultr/terraform-provider-vultr](https://github.com/vultr/terraform-provider-vultr)) | the vultr provider waits for the address and the snapshot before returning |
| vultr load balancer `ignore_changes = [health_check[0].path]`: a TCP health check reads back an empty path while the provider defaults it to `/`, so every plan proposes an update | `modules/vultr/loadbalancer.tf` | none filed ([vultr/terraform-provider-vultr](https://github.com/vultr/terraform-provider-vultr)) | the provider keeps the configured path for TCP checks (verify that a second plan is empty) |
| vultr load balancer addresses read from the API through `data.http.lb`, with the ids routed through `terraform_data.lb_ids`: `vultr_load_balancer.*.ipv4` can be empty after create, and the indirection keeps the read at plan time | `modules/vultr/loadbalancer.tf` | none filed (same provider as above) | the provider returns the address reliably after create: read `ipv4` directly and delete `lb_ids` and `data.http.lb` |
| vultr `vultr_snapshot_from_url` is a single attempt: when the fetch fails the platform deletes the record, so the resource stays in state with an id that no longer exists. `wait-for-snapshot.sh` prints the recovery, `terraform state rm 'module.ai_factory.vultr_snapshot_from_url.ai_factory[0]'`, before the next apply | `modules/vultr/scripts/wait-for-snapshot.sh`, `modules/vultr/image.tf` | none filed (same provider as above) | the provider reports a failed import as an error and removes the resource from state |
| exoscale signed API reads for the plan-time checks: `exoscale-api.sh` (mode `check`, EXO2-HMAC-SHA256 with `openssl`) behind `data.external.api_check` lists the instance types available to the organization per zone with their GPU count, the quotas (usage and limit), and the instances and network load balancers this cluster already holds. The provider has no data source for instance types, quotas or a network load balancer list, and the unsigned type list reports GPU types as unavailable for everyone | `modules/exoscale/scripts/exoscale-api.sh`, `modules/exoscale/availability.tf`, `external` in `modules/exoscale/versions.tf` | none filed ([exoscale/terraform-provider-exoscale](https://github.com/exoscale/terraform-provider-exoscale)) | the provider has data sources for the instance types available to the organization (per zone, with GPU count) and for quotas: read them natively and delete the `check` mode |
| exoscale control plane pool members read through the API: `exoscale-api.sh` (mode `members`) behind `data.external.cp_members` returns each member with its private network lease. No data source or attribute exposes the private address of a pool member, and the pool's `instances` attribute lists fewer members right after a scale call until the next refresh | `modules/exoscale/scripts/exoscale-api.sh`, `modules/exoscale/control-plane.tf` | none filed (same provider as above) | the provider exposes the private network address of pool members and lists new members right after a scale call: read them natively and delete the `members` mode; with the entry above, delete `exoscale-api.sh` and the `external` provider |
| `ZYPP_PCK_PRELOAD=0` on the build host | `modules/image-factory/templates/factory-common.sh.tftpl` | none filed (openSUSE Leap 16 mirrors return 404 for parallel package preload) | Leap 16 mirrors serve parallel preload requests |
| `include_deprecated = true` on the openSUSE Leap 16 jumphost AMI lookup: the current Leap 16 images carry a deprecation time, so the default lookup finds none | `data.aws_ami.jumphost` in `modules/aws/build.tf` | none filed (openSUSE publisher `679593333241`) | current Leap 16 AMIs are published without a deprecation time: drop `include_deprecated` |
| `ignore_changes = [description]` on `aws_ebs_snapshot_import`: VM Import stores its own description (`Created by AWS-VMImport service for import-snap-...`), the provider reads it back, and `description` forces replacement, so the second plan would replace the snapshot, the AMI and every node | `modules/aws/image.tf` | none filed ([hashicorp/terraform-provider-aws](https://github.com/hashicorp/terraform-provider-aws)) | the provider keeps the configured description or stops forcing replacement on it |
| aws node instances on an aliased provider with `max_retries = 3`: the SDK retries `InsufficientInstanceCapacity` (HTTP 500) up to `max_retries` (default 25, close to an hour) and ignores the resource `timeouts` | `examples/aws/main.tf` (`aws.nodes`), `configuration_aliases` in `modules/aws/versions.tf`, `provider` in `modules/aws/control-plane.tf` and `agent-nodes.tf` | [hashicorp/terraform-provider-aws#49863](https://github.com/hashicorp/terraform-provider-aws/issues/49863), [#43193](https://github.com/hashicorp/terraform-provider-aws/issues/43193) | the provider stops retrying `InsufficientInstanceCapacity`: remove the alias and pass the default provider only |
